# Veille du 2026-11-19 — vfx-roto-compositing-engineer

Méthode : 6 recherches web (12 derniers mois, sans répéter le 24/10), existence et versions vérifiées le 19/11 par l'API JSON de PyPI (`https://pypi.org/pypi/<paquet>/json`) et par `ffmpeg -filters` dans le conteneur. L'API GitHub est refusée dans cette session (dépôt non attaché) : les dépôts GitHub et Hugging Face cités ne sont PAS vérifiés. Les constats viennent de résumés de recherche (fiabilité moyenne) : toute règle changée doit d'abord être confirmée par une mesure locale.

## Constats

1. `rembg` 2.0.87 (PyPI, 2026-11-06, MIT), successeur de la 2.0.86 — https://pypi.org/project/rembg/ — rien à changer ; le coût de `birefnet-general` sur CPU est rapporté autour de 15 s par image (modèle ONNX de 973 Mo, contre 0,4 s pour u2net) sur un test unique — https://aireiter.com/blog/best-background-removal-api — `birefnet-portrait` reste réservé à UNE image clé et aux images de bornes (planche de bords), jamais à un lot de 1 000 images ; mesurer s/image avant.
2. Le scintillement du masque d'un détourage image par image est confirmé par un panorama d'avril 2026 (le matte bouge d'un ou deux pixels entre images) ; seuls des modèles à mémoire temporelle (MatAnyone) l'évitent — https://ice-ice-bear.github.io/posts/2026-04-13-matting-libraries — non applicable (licence, GPU), donc : `rvm` (déjà dans `cutout_video.py`) puis moyenne sur 3 images et flou de bord 2 à 4 px, comme dans la fiche ; aucun changement.
3. `dewatermark` 0.8.0 (PyPI, 2026-08-20, MIT) : CLI qui passe une retouche LaMa image par image via ffmpeg — https://pypi.org/project/dewatermark/ ; un outil voisin (static-ghost, non vérifié) annonce ≈ 2 h CPU pour 10 min de 1080p, même en ne traitant que la zone du logo — https://github.com/redredchen01/static-ghost — pour une incrustation d'ancien montage, essayer d'abord `delogo`, puis `removelogo` (masque), puis recouvrement par un bloc de design ; LaMa seulement sur UNE image et une zone recadrée, temps mesuré, si un fond complexe l'exige. Rien d'installé ni de lancé ici.
4. FFmpeg 8.0 (2025-08-22) et 8.1 (2026-03-16) : nouveautés = filtre Whisper, `colordetect`, `drawvg`, Vulkan/D3D12 ; aucune nouveauté de stabilisation ni de détourage dans les résumés — https://ubuntuhandbook.org/index.php/2026/03/ffmpeg-8-1-rockchip-jpeg-xs/ — le conteneur a ffmpeg 6.1.1 avec `vidstabdetect/transform`, `deshake`, `delogo`, `removelogo`, `chromakey`, `despill`, `scdet` (vérifié) : tout notre geste y est ; ne pas mettre à jour.
5. `mediapipe` 1.2.3 (PyPI, 2026-11-11, Apache-2.0) ; le segmenteur « selfie » carré 256×256 est donné à 33 ms par image sur le CPU d'un téléphone Pixel 6, entrée vidéo prise en charge — https://developers.google.com/edge/mediapipe/solutions/vision/image_segmenter — confirme son rôle de masque de contrôle (tête/mot, crâne non coupé) sur tout le lot, à bas coût ; toujours pas de matte final.
6. Depth Anything V3 : des exports ONNX de la version Small (Apache-2.0) circulent, un export int8 pour CPU annonce 0,18 s par photo (une photo, un Mac) ; Large et Giant sont CC-BY-NC ; licence de la Base contestée — https://huggingface.co/en970/depth-anything-v3-small-onnx et https://huggingface.co/SpatialHub/depth-anything-3-onnx (non vérifiés) — `depth_layers.py` reste sur Depth Anything V2 Small (Apache-2.0) ; un essai V3 Small sur UNE photo est possible hors production, après lecture de la licence amont, jamais Base, Large ni Giant.
7. Versions sorties : `opencv-python-headless` 5.1.0.95 (2026-11-17), `onnxruntime` 1.32.0 (2026-11-13) ; le conteneur a OpenCV 4.14.0.94 et onnxruntime 1.29.0 — https://pypi.org/project/opencv-python-headless/ et https://pypi.org/project/onnxruntime/ — l'écart se creuse (la veille du 24/10 citait OpenCV 5.0.0.93) : pas de migration en cours de projet ; un essai éventuel dans un environnement virtuel à part, sur 3 images de contrôle, entre deux productions.

## Écarté

- ONYX Ai Matte 2.5 (juin 2026, module OFX) — https://www.cgchannel.com/2026/03/onyx-ai-matte-automatically-generates-masks-from-video-footage/ : commercial, GPU, payant.
- MatAnyone « sur CPU avec trimap » (un seul billet, non confirmé) : licence non commerciale, déjà exclu.
- Background Matting V2 (exige une plaque de fond propre), MODNet (ancien) : sources clients sans fond uni ni plaque vide.
- `multi-delogo`, `videowipe`, `static-ghost`, `iopaint`, `transparent-background`, `matanyone` : absents de PyPI le 19/11 (ou dépôt non vérifiable) ; rien à installer.
- LaMa sur la vidéo entière : de l'ordre de 12 s de calcul par seconde de vidéo (estimation du billet) contre un recouvrement par un bloc de design, instantané.
- Aucune pratique d'agence de référence datée 2026 trouvée sur le détourage vidéo sur CPU : rien à ajouter côté méthode.
